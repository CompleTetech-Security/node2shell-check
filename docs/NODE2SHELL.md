# Node2Shell assessment methodology

Rule snapshot: **2026-10-23**. Covered identifier: **CVE-2026-111497**.

## What is being assessed

The Node.js project describes an out-of-bounds write in its bundled Brotli
decoder. Applications that decompress attacker-controlled Brotli input through
`node:zlib` can expose process memory to corruption, with possible crashes,
memory disclosure, or code execution. Node.js rates this issue high severity.
See the [official advisory](https://nodejs.org/en/blog/vulnerability/october-2026-security-releases).

This checker compares reported runtime versions with published upstream fixes.
It does not trigger the decoder, send compressed request bodies, test a crash,
or attempt code execution. **Exploitability is always `not_tested`.**

The checker does not download rules or silently refresh this table.

## Classification rules

| Evidence | Result | Interpretation |
| --- | --- | --- |
| One complete plain version below its branch's fix | `potentially_affected` | Reported upstream base is older than the fix; validate deployed package/build and exposure. |
| One complete plain version at/above its branch's fix | `fixed_version_reported` | Version comparison meets the table; actual deployment and package patches remain unverified. |
| Plain version on an older unsupported upstream line | `unsupported_runtime` | No upstream fix threshold for this line is supplied by this snapshot; obtain vendor guidance or upgrade. |
| Missing, malformed, partial, or conflicting versions | `unknown` | There is not one usable runtime version to compare. |
| Vendor-qualified, prerelease, or custom-build evidence | `unknown` | The upstream number alone cannot establish patch status. |
| Inconsistent decoder metadata or possible backport evidence | `unknown` | Reconcile the binary and build provenance before accepting an upstream-version verdict. |
| An uncovered future branch | `unknown` | Update rules from official evidence before assessing it. |

A leading `v` is accepted for ordinary Node.js version output. Qualifiers are
preserved rather than stripped to produce a more reassuring comparison.
Conflicting versions are not reduced to the newest or oldest value.

The [Node.js release schedule](https://github.com/nodejs/Release#release-schedule)
and advisory identify the importance of supported releases. An
`unsupported_runtime` result is an upgrade/review finding, not a claim that this
checker reproduced CVE-2026-111497 on every historical Node.js release.

## Three evidence modes

### Public website metadata

Only explicit Node.js version disclosures are version candidates. A public
header can be stale, spoofed, generated by a proxy, or inconsistent across a
load-balanced service. It is never independent runtime attestation.

Express, Next.js, or similar framework indicators are hints. A framework version
is not a Node.js version. HTML assets can come from a static export or a different
host. Missing indicators do not establish that Node.js is absent.

A response header such as `Content-Encoding: br` does not establish that the
application accepts or decodes attacker-controlled Brotli request bodies. The
checker requests identity encoding and does not decompress the response.

### Operator-supplied versions

`--node-version` compares a supplied version without making network requests.
The operator is responsible for obtaining that value from the relevant runtime.
A version copied from a Dockerfile, development machine, deployment label, or
package manifest may differ from the process actually serving traffic.

### Local collector inventory

`collect-runtime.cjs` records metadata for the Node.js process executing the
collector. Run it in the actual container or runtime environment you intend to
assess. A host installation does not describe every container, function, worker,
or separately bundled runtime.

The collector does not prove how a vendor built or patched the binary. Its
`build_source` is `unknown` by default. Brotli metadata is useful context, but
does not override the Node.js release table or establish that a backport is
present. The checker does not infer exploitability from collected metadata.

The collector also records whether Brotli decompression APIs and the
`BROTLI_DECODER_ERROR_FORMAT_BLOCK_SWITCH` constant are present. It does not call
the decompression APIs. A reported constant value of `-17` below the upstream
version threshold is treated as possible backport/custom-build evidence and
keeps the assessment `unknown`. Conflicting detailed metadata likewise prevents
a fixed-version result. A missing constant in sparse metadata does not by
itself prove a vulnerability; a constant's presence does not prove a complete
patch or establish which binary serves application traffic.

## What an administrator should verify

1. Identify each deployed Node.js runtime, including container images, workers,
   serverless functions, and binaries that embed Node.js.
2. Check its actual version and package/build provenance. Consult the vendor for
   backports or customized runtimes rather than assuming the upstream version
   is the complete patch record.
3. Update affected supported lines to their fixed release or a newer maintained
   release. Move unsupported upstream runtimes to a supported line.
4. Rebuild and redeploy affected images or artifacts, restart the serving
   processes, and collect the version again from the deployed environment.
5. Review paths that decompress untrusted Brotli input. The checker does not
   perform that source/configuration review or verify a compensating control.

A successful scan, a missing header, or a WAF response does not establish that a
service has been patched. Keep operational fetch failures separate from the
version result, and preserve the original evidence when reviewing a finding.

## Scope and exclusions

The assessment is for Node.js versions. It does not apply Node.js thresholds to
Bun, browser runtimes, standalone Brotli libraries, or arbitrary packages with a
similar version number. It is not a general vulnerability scanner and does not
claim to assess all vulnerabilities fixed in the same security release.
